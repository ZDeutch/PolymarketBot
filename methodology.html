⚡ How It Works

Finding Mispriced Chess
Prediction Markets

A plain-English walkthrough of how PolymarketBot models tournament win probabilities and identifies edges against market prices.

The Big Idea

Prediction markets let you bet on who wins a chess tournament. Like any market, they can be wrong. PolymarketBot builds its own probability model and bets when the model disagrees significantly with the market price.

What is "edge"?

edge = model_probability − market_price

// edge > 0 → market underprices the player → BUY YES
// edge < 0 → market overprices the player → BUY NO
// |edge| < 8% → within noise, no bet

For example: if the model says Magnus Carlsen has a 33% chance of winning Norway Chess, but Kalshi is selling YES contracts at 61¢, the edge is −28%. The market thinks he's nearly twice as likely to win as the model does — so we buy NO (betting against Carlsen winning).

The Pipeline

Every run of the bot follows these 7 steps automatically.

1

Fetch tournament metadata from Lichess

Pulls the current round results and player list from the Lichess Broadcast API. If the tournament hasn't started yet (no broadcast), uses a pre-configured player list and a synthetic schedule.

2

Get player ratings

Loads current FIDE classical ratings from a hardcoded table (updated after each rating list). For a handful of players, also checks Chess.com — but only when the Chess.com rating is known to be accurate (some top GMs have inflated online ratings).

3

Build the remaining schedule

Computes all remaining games in the round-robin, excluding games already played. Handles single and double round-robins automatically based on total rounds vs. player count.

4

Run 50,000 Monte Carlo simulations

Simulates the full remaining tournament 50,000 times. Each iteration plays out every remaining game using the Elo win probability formula, the Kryukov draw-rate model, and blended TPR ratings. Counts how often each player wins to get a win probability.

5

Fetch market prices

For Polymarket events, hits the Gamma API → CLOB API to get the live YES midpoint price. For Kalshi, reads from hardcoded prices manually updated before each run (Kalshi doesn't have a public API).

6

Calculate edges and size positions

Compares model probabilities to market prices. For any edge ≥ 8%, computes a quarter-Kelly stake size. Caps total tournament exposure at 5% of bankroll ($500 on a $10K bankroll).

7

Log to positions.csv

Writes every actionable position (those with a non-zero stake) to a CSV file with the date, tournament, exchange, edge, and stake size. The dashboard reads this file live.

The Model

Three components make the simulation more accurate than naive Elo alone.

1 — Elo Win Probability

How likely is player A to beat player B in a single game?
P(A wins) = 1 / (1 + 10^((R_B − R_A) / 400))

// White gets +35 Elo advantage before the calculation
// The leftover probability (after P(A wins) and P(draw)) goes to B

Standard FIDE Elo formula. A 200-point gap means the stronger player wins ~76% of decisive games. The +35 white bonus is a well-documented first-move advantage at elite level.

2 — Kryukov Draw-Rate Model

How likely is this specific game to be drawn?
draw% = −|ΔR| / 32.49
        + exp((avg_rating − 2254.7) / 208.49)
        + 23.87

// avg_rating = average of both players' ratings
// |ΔR| = absolute rating difference

At the top level, games between equally matched 2800+ players draw more than 60% of the time. The exponential term captures this surge. A bigger rating gap means fewer draws (one player is just better). This beats simpler draw models — tested against 2024–2026 elite tournament data.

3 — Tournament Performance Rating (TPR) Blending

Static FIDE ratings miss recent form. TPR captures it.
tpr_weight = min(elite_games / 15, 1.0) × 0.55
fide_weight = 1.0 − tpr_weight

adjusted_rating = fide_weight × fide_elo + tpr_weight × tpr

velocity = (tpr − fide_elo) × 0.15
adjusted_rating += clamp(velocity, −50, +50)

// tpr computed from 2600+ opposition games only
// 650+ players in db across 7 tournaments (2024–2026)

FIDE ratings update monthly and lag performance. A player who just won the Candidates tournament is probably stronger than their FIDE number suggests. TPR from recent elite games captures current form, weighted by how many games we have (more games = more reliable).

Position Sizing

How much to bet, given an edge.

Quarter-Kelly Criterion

f* = (b·p − q) / b

// b = net odds paid on a win
// p = model win probability
// q = 1 − p (probability of loss)

stake = (f* × 0.25) × bankroll
stake = max(stake, $100)

Kelly tells you the fraction of bankroll that maximizes long-run growth. We use quarter-Kelly (25%) as a conservative hedge against model error. A wrong model with full Kelly sizing leads to ruin — quarter-Kelly survives mistakes while still being profitable if the model is right.

Common Questions

Why chess specifically?
Chess has well-understood rating systems (FIDE Elo) and rich historical data. Elo is a proven, calibrated predictor of game outcomes — better than most sports. This gives the model a real statistical foundation rather than vibes.
Why stop betting after 4 rounds?
The pre-tournament edge disappears as results come in. By round 5+, the market has already observed half the tournament and repriced aggressively. Our edge is highest before round 1, when we have the most information advantage over the market.
Why does the model think Carlsen is so much less likely to win than the market?
In a 6-player double round-robin, there are 5 opponents each nearly as strong as Carlsen (2730–2762 Elo). Combinatorially, Carlsen can't win every tournament. His base rate in a perfectly even 6-player field would be ~17%. Even with his rating advantage, 33% is the right number — the market's 61% is the one that's hard to justify mathematically.
What's a Tournament Performance Rating (TPR)?
TPR measures how well a player actually performed in a tournament, given their opponents' ratings. It's like a live Elo that only looks at elite games (2600+ opposition). Javokhir Sindarov won the 2026 Candidates — his TPR from that tournament was far above his static FIDE rating, so the model correctly assigned him higher win probability for future events.
Is this real money?
The bankroll and stakes shown are simulated. This is a research and model-validation project.
